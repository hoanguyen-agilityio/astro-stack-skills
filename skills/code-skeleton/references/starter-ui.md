# Starter UI — reusable layout, shared components and the welcome page

What `code-skeleton` writes in step 3, after the layers are installed. The point is not the welcome page itself, which the first
real feature replaces, but the **pieces it is built from**: a layout every page reuses, a few
app-wide components with stories, and one place for the site's name and navigation. Later
features compose these instead of starting each page from `<main class="mx-auto …">`.

Verified with Astro 5.18, React 19, Tailwind 4, shadcn 4 (`nova`), Storybook 10.6: lint,
`astro check`, 5/5 tests, `astro build` and `storybook build` pass; the page renders in light and
dark, the theme persists without a flash, the counter island hydrates, and `/404` renders.

## What goes where

The whole `src/` the skeleton leaves (starter UI pieces plus the plumbing from `project-files.md`):

```
src/
├── pages/                         # routes; index.astro, 404.astro, __test__/index.test.ts
├── layouts/
│   ├── BaseLayout.astro           # <html> shell: meta, favicon, theme script before paint
│   └── AppLayout.astro            # BaseLayout + skip link + SiteHeader + <main> + SiteFooter
├── config/site.ts                 # name, description, nav links: the one place to change them
├── components/
│   ├── ui/                        # shadcn primitives (generated, then owned): button, card, badge
│   ├── common/                    # app-wide, no feature knowledge, props + slots only
│   │   ├── Container/             # max width + gutters (size sm | md | lg)
│   │   ├── PageHeader/            # eyebrow, h1, description, `actions` slot
│   │   ├── LinkCard/              # card-shaped link with `icon` slot
│   │   └── ThemeToggle/           # React island, light/dark
│   ├── layout/                    # the app shell's parts, used only by layouts
│   │   ├── SiteHeader/            # brand, nav from siteConfig, ThemeToggle
│   │   └── SiteFooter/
│   └── home/                      # the welcome page's own pieces (replace them later)
│       ├── Hero/  GetStarted/  CounterButton/
│       └── stack.ts               # the cards' data
├── lib/utils.ts                   # generated by shadcn: leave it to shadcn
├── libs/
│   ├── orpcClient.ts              # the one oRPC client factory
│   ├── theme.ts                   # applyTheme / toggleTheme (class `.dark` + localStorage)
│   └── __test__/orpcClient.test.ts  # base URL, bearer header (project-files.md)
├── services/  types/  mocks/      # empty (.gitkeep): integrate-api and develop-feature fill them
└── styles/global.css
public/favicon.svg
.storybook/main.ts, preview.ts
```

`src/lib/` belongs to shadcn (`shadcn add` resolves imports from `components.json`, so never move
it); `src/libs/` belongs to the app.

Each component is one folder, the layout of the team's `space` apps:

```
src/components/<feature>/
├── <Name>/
│   ├── index.astro | index.tsx  # the component
│   ├── <Name>.stories.tsx       # its stories (Astro and React alike)
│   └── __test__/index.test.tsx  # React only; .astro is covered by its story and the page test
├── format.ts, load<Resource>.ts # feature helpers, not components
└── __test__/<helper>.test.ts
```

Import React components from the folder (`@/components/common/ThemeToggle`) and Astro ones by
file (`@/components/common/Container/index.astro`). Tests import with `from '..'`, stories with
`from '.'` or `'./index.astro'`. Test folders are `__test__/` everywhere.

Rules a later feature follows (they go into `DESIGN.md` too):

| Kind of component | Folder | May import |
|---|---|---|
| shadcn primitive | `components/ui/` | nothing app-specific |
| App-wide building block, no domain words in its props | `components/common/<Name>/` | `ui/`, `libs/`, `config/` |
| Part of the app shell | `components/layout/<Name>/` | `common/`, `ui/`, `config/` |
| Feature component | `components/<feature>/<Name>/` | `common/`, `ui/`, its own feature's helpers |

- Every page uses `AppLayout` (or `BaseLayout` for a page without the shell, such as a print view)
  and puts its content in a `Container`, starting with a `PageHeader`.
- Feature folders never import from another feature folder. When a second feature needs a
  component, move it to `common/` and drop the domain words from its props (`OrderCard` →
  `LinkCard`-style generic props).
- Variation goes through props and named slots, not copies: `Container size="sm"`,
  `<a slot="actions">` in `PageHeader`, `<Icon slot="icon">` in `LinkCard`.
- Islands go into `.astro` components through a slot (`GetStarted` takes the counter in its
  `demo` slot), so the `.astro` component keeps a server-rendered story and the island keeps its
  own React story.

`src/libs/theme.ts`:

```ts
export type Theme = 'light' | 'dark';

/** Also read by the inline script in BaseLayout.astro, which sets the theme before first paint. */
export const THEME_STORAGE_KEY = 'theme';

export const currentTheme = (): Theme =>
  document.documentElement.classList.contains('dark') ? 'dark' : 'light';

export const applyTheme = (theme: Theme): void => {
  document.documentElement.classList.toggle('dark', theme === 'dark');
  try {
    localStorage.setItem(THEME_STORAGE_KEY, theme);
  } catch {
    // Storage blocked (private mode): the theme still applies to this page.
  }
};

export const toggleTheme = (): Theme => {
  const next = currentTheme() === 'dark' ? 'light' : 'dark';
  applyTheme(next);
  return next;
};
```

`src/layouts/BaseLayout.astro`:

```astro
---
import '@/styles/global.css';

import { siteConfig } from '@/config/site';

interface Props {
  title: string;
  description?: string | undefined;
}

const { title, description = siteConfig.description } = Astro.props;
const fullTitle =
  title === siteConfig.name ? title : `${title} · ${siteConfig.name}`;
---

<!doctype html>
<html lang="en">
  <head>
    <meta charset="utf-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1" />
    <meta name="description" content={description} />
    <link rel="icon" type="image/svg+xml" href="/favicon.svg" />
    <title>{fullTitle}</title>
    <!-- Runs before paint so a dark-mode visitor never sees a white flash. Key: libs/theme.ts. -->
    <script is:inline>
      (() => {
        let stored = null;
        try {
          stored = localStorage.getItem('theme');
        } catch {
          // Storage blocked: fall back to the system preference.
        }
        const dark = stored
          ? stored === 'dark'
          : matchMedia('(prefers-color-scheme: dark)').matches;
        document.documentElement.classList.toggle('dark', dark);
      })();
    </script>
  </head>
  <body class="min-h-dvh antialiased">
    <slot />
  </body>
</html>
```

The inline script repeats the storage key because `is:inline` scripts cannot import. It runs
before the body paints, so a visitor who chose dark never sees a light flash.

`src/components/common/ThemeToggle/index.tsx`:

```tsx
import { MoonIcon, SunIcon } from 'lucide-react';

import { Button } from '@/components/ui/button';
import { toggleTheme } from '@/libs/theme';

/**
 * Switches the `.dark` class on <html>. The icon follows the class through `dark:` variants, so
 * the server render and the hydrated island always match.
 */
export const ThemeToggle = () => (
  <Button
    variant="ghost"
    size="icon"
    aria-label="Toggle dark mode"
    onClick={() => toggleTheme()}
  >
    <SunIcon className="hidden dark:block" aria-hidden="true" />
    <MoonIcon className="dark:hidden" aria-hidden="true" />
  </Button>
);
```

No state: both icons render and `dark:` classes pick one, so the server HTML and the hydrated
island always agree (no hydration mismatch), whatever theme the visitor stored.

```tsx
import { render, screen } from '@testing-library/react';
import userEvent from '@testing-library/user-event';
import { afterEach, describe, expect, it } from 'vitest';

import { THEME_STORAGE_KEY } from '@/libs/theme';

import { ThemeToggle } from '..';

describe('ThemeToggle', () => {
  afterEach(() => {
    document.documentElement.classList.remove('dark');
    localStorage.clear();
  });

  it('switches to dark and back, and remembers the choice', async () => {
    render(<ThemeToggle />);
    const toggle = screen.getByRole('button', { name: 'Toggle dark mode' });

    await userEvent.click(toggle);
    expect(document.documentElement).toHaveClass('dark');
    expect(localStorage.getItem(THEME_STORAGE_KEY)).toBe('dark');

    await userEvent.click(toggle);
    expect(document.documentElement).not.toHaveClass('dark');
    expect(localStorage.getItem(THEME_STORAGE_KEY)).toBe('light');
  });
});
```

```tsx
import { useState } from 'react';

import { Button } from '@/components/ui/button';

interface CounterButtonProps {
  readonly initialCount?: number;
}

export const CounterButton = ({ initialCount = 0 }: CounterButtonProps) => {
  const [count, setCount] = useState(initialCount);

  return (
    <Button
      size="lg"
      variant="outline"
      className="tabular-nums"
      onClick={() => setCount((n) => n + 1)}
    >
      {`Count is ${count}`}
    </Button>
  );
};
```

`src/pages/__test__/index.test.ts`, which proves the shell renders around both pages (the
Container API pattern `develop-feature` uses for page tests):

```ts
// @vitest-environment node
import { getContainerRenderer } from '@astrojs/react';
import { experimental_AstroContainer as AstroContainer } from 'astro/container';
import { loadRenderers } from 'astro:container';
import { describe, expect, it } from 'vitest';

import { siteConfig } from '@/config/site';
import NotFoundPage from '@/pages/404.astro';
import HomePage from '@/pages/index.astro';

const render = async (page: typeof HomePage, url: string) => {
  const container = await AstroContainer.create({
    renderers: await loadRenderers([getContainerRenderer()]),
  });
  return container.renderToString(page, { request: new Request(url) });
};

describe('pages', () => {
  it('renders the home page inside the app shell', async () => {
    const html = await render(HomePage, 'http://localhost/');

    expect(html).toContain(`<title>${siteConfig.name}</title>`);
    expect(html).toContain('href="#main"');
    expect(html).toMatch(/<a[^>]*href="\/"[^>]*aria-current="page"/);
    expect(html).toContain(`Welcome to ${siteConfig.name}`);
    expect(html).toContain('Count is 0');
  });

  it('renders the 404 page with a way back home', async () => {
    const html = await render(NotFoundPage, 'http://localhost/missing');

    expect(html).toContain(
      `<title>Page not found · ${siteConfig.name}</title>`,
    );
    expect(html).toContain('Back to home');
  });
});
```

## Notes

- `CounterButton` renders its label as one template string. `Count is {count}` would make React
  write `Count is <!-- -->0` on the server, which a page test cannot match as text.
- `.astro` stories pass slots as HTML strings (`args.slots.<name>`), so a story's slot content
  uses plain markup with the same utility classes. Islands inside an `.astro` component are
  covered by their own React story.
- `w-3xl`, `h-72`, `bg-linear-to-tr`, `supports-backdrop-filter:` are stock Tailwind v4
  utilities. Do not replace them with arbitrary values.
- Lint ignores nothing new; `astro check` covers the `.astro` files and their stories.
